# Internacionalização

`next-intl`, dois locales (`pt-br` padrão, `en`), mensagens em `messages/{locale}.json`.

## Texto de UI é sempre traduzido 🔴 (código novo) / mutirão em ondas (legado)

Todo texto visível ao usuário passa por `useTranslations`/`t(...)`. Regra bloqueante para
código novo ou tocado; o legado que ainda tinha string hardcoded foi migrado em ondas — onda 1
(auth, teams, settings, notificações) e onda 2 (editor, canvas) já concluídas.

### Isenções declaradas

Sem uma lista de isenções explícita, o check de chave órfã (abaixo) nunca poderia ser ligado —
toda string que parece texto de UI teria que ter chave, inclusive as que não deveriam.

**Isento:**
- Nome próprio (`Anthropic`, `Scira AI`, nomes de provedor OAuth como `GitHub`/`Google`).
- Nome de linguagem de programação (`TypeScript`, `Rust`).
- Nome de locale (`Português`, `English`) — no seletor de idioma, o nome do idioma não se
  traduz para o idioma que ele nomeia.
- Código de exemplo dentro de um bloco (`# Notas` como conteúdo inicial de um bloco de texto,
  não como rótulo de UI).

**Explicitamente não isento** — casos que parecem exemplo mas são UI real:
- Texto de UI dentro de um exemplo interativo (`"Olá React!"` num preview de componente).
- `<title>` de SVG — é acessibilidade, não decoração (`"Gráfico de dados"` em `chart-svg.tsx`).

## ICU + chave sempre literal 🔴

Plural e interpolação usam sintaxe ICU com parâmetros — nunca concatenação à mão
(`${n} ${t("dias")}` quebra plural em pt-BR e en de formas diferentes). A chave passada a
`t(...)` é **sempre um literal de string**, nunca `t(\`prefixo.${var}\`)`. Concatenar a chave em
runtime impede o check de chave órfã (abaixo) de saber que aquela chave está em uso.

### Enum → chave, nunca enum → texto

Quando o texto a mostrar depende do valor de um enum (status de submissão, tipo de gráfico,
dificuldade de desafio), o mapa fica em um `Record<Enum, string>` `as const` — mas o valor do
mapa é a **chave** de tradução, não o texto já traduzido:

```ts
const SUBMISSION_STATUS_LABEL_KEYS: Record<SubmissionStatus, string> = {
  queued: "status.queued",
  running: "status.running",
  done: "status.done",
};

t(SUBMISSION_STATUS_LABEL_KEYS[status]);
```

não

```ts
const SUBMISSION_STATUS_LABELS: Record<SubmissionStatus, string> = {
  queued: "Na fila",
  running: "Executando",
};
```

O segundo padrão hardcoda um locale dentro do mapa e não escala para o segundo idioma. O
primeiro mantém a chave estática (rastreável pelo check de órfã) mesmo com o valor sendo
escolhido em runtime pelo enum.

### Exceção real: chave vinda de fora do TypeScript

Três famílias de chave são resolvidas por um código que **não é um enum fechado no TS** —
vem do backend, de um provedor OAuth, ou de um catálogo carregado em runtime. Não há como
tornar essas chaves literais sem duplicar a fonte de verdade, então ficam isentas do check de
órfã (com a justificativa presa ao código em `scripts/validate-i18n.mjs`):

- `api_errors.*` — `handleApiError` chama `t(errorCode)`, e `errorCode` é uma string vinda do
  backend. Cobertura garantida pelo terceiro check, não pelo segundo.
- `login.errors.*` — código de erro OAuth cruzado com o slug do provedor (`{slug}_response_failed`
  etc.) — conjunto aberto, cresce com provedor novo.
- `perm.*` — a chave é `permission.key` do catálogo de permissões
  ([permissions-design.md](../permissions-design.md)), carregado em runtime; o componente já
  guarda com `tp.has(perm.key)` antes de usar.

Toda chave fora dessas três famílias que usa interpolação de variável na própria chave é bug,
não exceção nova — resolva convertendo para um `Record<Enum, string>` como acima.

## Servidor não produz texto de UI 🔴

O backend não decide string visível ao usuário. `api_create_notebook`, `api_create_team_page` e
`api_clone_notebook` recebem o título e o conteúdo do bloco inicial no corpo da requisição,
já traduzidos pelo cliente no locale ativo — o servidor não tem `"Nova Página"`/`"Novo
Bloco"` hardcoded em lugar nenhum. Antes desta regra, um usuário em `en` criava notebook com
título em pt-BR, porque o servidor decidia o texto sem saber o locale de quem pediu. Raciocínio
completo e as alternativas descartadas em
[0002-server-does-not-decide-notebook-text](../decisions/0002-server-does-not-decide-notebook-text.md).

## Logs e mensagens internas do servidor em en-US 🔴

Consequência da reversão do Q10 ([comment-guide.md](comment-guide.md)): `tracing::info!`,
`warn!`, `error!`, `println!`, e a mensagem de `stderr` que o executor de sandbox devolve em
caso de erro interno, são todos en-US. Isso é distinto de texto de UI (que é sempre traduzido) —
log e diagnóstico interno não têm locale de usuário, então en-US é a escolha única, não uma
tradução.

## Três checks no CI 🔴

`pnpm validate:i18n` (`scripts/validate-i18n.mjs`), no job `frontend-test`:

1. **Paridade de chaves** — toda chave em `pt-br.json` existe em `en.json` e vice-versa.
2. **Nenhuma chave órfã** — definida em algum dos dois locales e nunca referenciada em código
   (varre `app/`, `components/`, `context/`, `domain/`, `features/`, `hooks/`, `lib/`,
   `schemas/`, `stores/`, `types/`, buscando o literal da chave, com as isenções descritas
   acima). Achado real na primeira execução: ~40 chaves de UI que não existia mais — sidebar de
   backup antigo, editor de cargo legado, fluxo de autoria de desafio nunca finalizado.
3. **Todo `errorCode` gerado tem chave em `api_errors`, nos dois locales.** É o gap que vale
   sozinho: sem ele, `handleApiError` mostra `PERMISSION_DENIED` cru na tela em vez do texto
   traduzido. Achado real na primeira execução: 6 códigos gerados sem chave
   (`ERROR_SENDING_EMAIL`, `PERMISSION_DENIED`, `LAST_LOGIN_METHOD`, `UNIQUE_VIOLATION`,
   `FOREIGN_KEY_VIOLATION`, `NOT_FOUND`).

## Mudou X ⇒ verifique Y

- `ApiError` ganha variante nova ⇒ `pnpm generate:error-codes` + chave em `api_errors` nos dois
  locales, ou o check 3 falha no CI.
- Enum de domínio novo precisa de label na UI ⇒ `Record<Enum, string>` de chave, nunca de texto;
  ver a seção "enum → chave" acima.
- Componente novo com texto visível ⇒ `useTranslations`, nunca string literal — as únicas
  exceções são as quatro isenções declaradas no topo deste doc.
- Rota de criação/clonagem de notebook muda de assinatura ⇒ confirme que o texto inicial
  continua vindo do cliente, não voltando a ser decidido no servidor.
