# Acessibilidade — foco, teclado, aria

O editor de notebook é majoritariamente mouse/touch por natureza (blocos arrastáveis, canvas de
desenho). Este doc declara onde a regra de teclado se aplica e onde, deliberadamente, não se
aplica — para que a lacuna seja escopo decidido, não omissão.

## Reordenação de blocos: já acessível por teclado, formaliza a regra 🟡 (Q120)

`reorder-item.tsx:70-91` já tem botões `<button aria-label="Mover bloco para cima/baixo">`
paralelos ao drag-and-drop (`Reorder.Item` do framer-motion) — são elementos nativos,
focáveis e operáveis por teclado sem esforço adicional. A regra formaliza o padrão: **toda
operação de reordenação exposta via drag precisa do equivalente discreto em botão**, porque ao
contrário do canvas de desenho (abaixo), mover um item numa lista tem equivalente discreto
natural — não é reinventar a ferramenta.

## Canvas de free-drawing: fora do escopo de teclado; toolbar em volta é 100% navegável 🟡 (Q119)

Desenho à mão livre não tem equivalente discreto de teclado sem reinventar a ferramenta —
"mover o pincel um pixel por tecla" não é o mesmo produto. A superfície de desenho em si
(`free-drawing-cell.tsx`) fica documentada como fora do escopo de navegação por teclado, e isso
é limitação conhecida, não pendência silenciosa.

O que **é** escopo: toda ferramenta, brush, ação de exportar/fullscreen/modo foco em volta do
canvas é navegável e operável por teclado. `free-drawing-cell.tsx:1078-1414` já cobre boa parte
disso com `aria-label` real (não texto decorativo) em cada botão — `focus_mode`, `fullscreen`,
`export_png`, seleção de forma geométrica (`GEO_SHAPE_LABEL_KEYS`), seleção de ferramenta
(`TOOL_LABEL_KEYS`), seletor de brush (`brushes_aria`). Botão novo na toolbar do canvas segue o
mesmo padrão: `aria-label` traduzido, nunca decorativo.

## WCAG AA obrigatório, com lint de contraste bloqueando PR 🔴 (Q121)

Todo par cor de texto/cor de fundo do design system passa a atender AA (4.5:1 para texto normal,
3:1 para texto grande) como piso, verificado por lint automatizado — não por revisão humana
lembrando de checar. Cor nova (token de tema, variante de botão, estado de erro/sucesso) só
mescla se o lint passar.

Antes desta regra, o único caso de a11y corrigido no projeto foi `chart-svg.tsx:88-92`
(`role="img"` + `<title>`) — e só porque Q42 decidiu não isentar gráfico da tradução, não porque
havia regra de contraste ou de aria além disso. A intenção agora é que aria/foco/teclado deixem
de depender de um caso específico ter sido notado.

## Padrão de foco/teclado em elemento interativo não nativo ⚪

`text-block.tsx:44-52` já é a referência: `role="button"` + `tabIndex={0}` + `onKeyDown`
tratando `Enter`/`Espaço`, corrigido na etapa 13 depois de um `biome-ignore` com
texto-placeholder nunca preenchido. Todo elemento interativo que não é `<button>`/`<a>` nativo
segue o mesmo padrão — é preferível usar o elemento nativo sempre que possível, e este padrão só
se aplica quando não é possível (ex.: item dentro de um componente de terceiro que já define a
estrutura do DOM).

## Mudou X ⇒ verifique Y

- Nova operação de reordenação/movimentação de item numa lista (não só bloco de notebook) ⇒
  precisa do par drag + botão discreto do Q120, não só do gesto de arrastar.
- Nova ferramenta ou botão na toolbar do canvas de desenho ⇒ `aria-label` traduzido (nunca
  decorativo) e navegável por teclado; a área de desenho em si continua fora do escopo (Q119).
- Cor nova adicionada ao design system (token de tema, variante de componente) ⇒ passa pelo
  lint de contraste do Q121 antes de mesclar.
- Elemento interativo novo que não é `<button>`/`<a>` nativo ⇒ segue o padrão de
  `role`/`tabIndex`/`onKeyDown` de `text-block.tsx`, com preferência por usar o elemento nativo
  quando a estrutura do DOM permitir.
